# 냉장고 재료 · 메뉴 추천 (fridge-menu)

냉장고 재료를 칩으로 고르고 드래그로 우선순위를 정하면, AI에 바로 붙여넣을 수 있는 레시피 검색 프롬프트를 만들어주는 React 웹앱입니다.

- 라이브: https://kkongkkong2da.github.io/fridge-menu/
- 기술 스택: React 18, Vite 5, @dnd-kit, JavaScript(ES2020), CSS 변수, GitHub Actions + Pages
- 버전: v1.6.3r (기능 변화 없이 코드를 정리한 리팩토링 버전)

## 제작 목적

코드 부트캠프에서 React를 배우며, JavaScript와 React를 중심으로 프론트엔드 전반을 활용해 만든 웹앱입니다. 냉장고에 재료는 많은데 오늘 뭘 먹을지 떠오르지 않는 불편에서 출발했고, 개발자이면서 실제 사용자인 제가 직접 쓰려고 만들었습니다.

대상은 냉장고에 재료가 충분하지만 마땅한 메뉴가 생각나지 않을 때, 아이디어를 얻고 싶은 사람입니다.

### 레시피 데이터베이스를 만들지 않은 이유

레시피를 직접 데이터로 넣지 않고, 재료 선택 결과를 검색용 프롬프트로 바꿔 Google의 AI 답변으로 추천받게 했습니다.

- 분량: 레시피를 많이 넣을수록 데이터가 방대해집니다.
- 정형화: 레시피는 정해진 형식으로 담기 어렵습니다.
- 유연성: 재료 조합에 맞춰 그때그때 추천받을 수 있습니다.
- 이어 묻기: 답변에 이어 "면요리로", "3개만 더", "2인분 기준", "일식으로", "불 없이" 같은 질문으로 범위를 넓히거나 좁힐 수 있습니다.

### 다른 방법을 써보고 내린 판단

- 레시피 사이트: 재료가 적고 딱 맞을 때 적합합니다. 재료가 많은 냉장고에서 폭넓은 추천을 받기에는 맞지 않았습니다.
- 네이버: 한식처럼 한국에서 흔한 요리를 찾을 때는 도움이 됩니다. 다만 검색 결과에 AI 답변이 바로 나오지 않고, 검색창 글자 수 제한 때문에 긴 프롬프트가 동작하지 않습니다. 직접 복사해서 붙여넣는 편이 나았습니다.
- Google: 최상단에 AI 답변이 나오고, 이어서 질문하기에 가장 편했습니다. 추천이 비슷하게 쏠리는 경우가 있지만, 이어 묻기로 방향을 바꿀 수 있습니다.

## 핵심 설계 원칙

재료 나열 순서가 곧 우선순위인데, 기존 체크리스트 앱은 이 정보를 전달하지 못합니다. 이 앱은 우선순위를 색(임박 여부)과 드래그 순서로 표현하고, 화면에 보이는 순서를 그대로 검색 프롬프트로 만듭니다. 설계 원칙은 단일 소스입니다.

```
저장된 chips 배열 순서 = 화면 칩 순서 = 프롬프트 재료 순서
```

세 가지가 모두 하나의 배열에서 나오기 때문에, 드래그로 순서를 바꾸면 저장, 화면, 프롬프트, 새로고침 후 상태가 항상 같은 순서를 유지합니다.

## 주요 기능

- 재료 칩: 7개 카테고리, 67종. 칩을 누르면 파랑(사용) → 빨강(임박) → 회색(제외) 순으로 바뀝니다.
- 드래그 정렬: 같은 카테고리 안에서만 순서를 바꿀 수 있습니다.
  - PC: 누른 채 5px 이동하면 바로 시작
  - 모바일: 0.6초 길게 누르면 시작. 그 전에 손가락이 10px 이상 움직이면 취소되어 세로 스크롤을 방해하지 않습니다.
- 재료 관리: 카테고리별 재료 추가(＋), 삭제(×), 모두 선택/해제
- 모바일 레이아웃(640px 이하): 2행을 넘는 카테고리는 접어두고 ▼/▲ 버튼으로 펼칩니다. 펼침 상태는 새로고침 후에도 유지됩니다.
- 레시피 종류: 간단, 식사, 안주, 브런치, 디저트 중 복수 선택
- 프롬프트 생성: 임박 재료는 반드시 쓰도록, 나머지는 선택 재료로 구분해 전달합니다. [복사]와 [Google 검색] 버튼을 제공합니다.

```
· 반드시 사용해야 하는 임박 재료: 달걀, 우유
· 위의 임박 재료를 꼭 쓰고, 아래 재료들 일부로 만들 수 있는 레시피를 추천해줘:
  양파, 대파, 치즈
· 소스, 오일, 조미료, 장류 모두 보유
· 종류: 간단, 안주
```

## 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | React 18 | 컴포넌트 분리와 커스텀 훅으로 상태 로직을 격리 |
| 빌드 | Vite 5 | 빠른 개발 서버, `base: './'`로 Pages 하위 경로 배포 대응 |
| 드래그앤드롭 | @dnd-kit | 마우스와 터치 센서를 따로 구성 가능 |
| 스타일 | CSS 변수 | 칩 색상을 토큰으로 관리 |
| 저장 | localStorage (버전 키) | 백엔드 없는 정적 앱, 스키마 변경 시 키 버전으로 대응 |
| 배포 | GitHub Actions | main에 푸시하면 자동 빌드 및 배포 |

## 디렉터리 구조

```
fridge-menu/
├── .github/workflows/deploy.yml   # main 푸시 시 Pages 자동 배포
└── app/
    ├── src/
    │   ├── App.jsx                # 화면 조립, 드래그 목록 스냅샷 관리
    │   ├── components/            # Chip, ZoneList, KindPicker, ResultCard, MigrationNotice
    │   ├── hooks/                 # useFridge, useLongPressDrag
    │   ├── lib/                   # React 없는 순수 로직 (storage, prompt, clipboard)
    │   └── data/materials.js      # 7개 카테고리 67종
    └── verify/                    # node로 실행하는 검증 스크립트
```

`lib/`는 React에 의존하지 않는 순수 함수 모듈입니다. UI와 로직의 경계를 물리적으로 나눈 덕분에 브라우저 없이 node만으로 로직을 검증할 수 있습니다.

## 설계 포인트

### 드래그 파이프라인
드롭 위치 판정부터 저장까지 같은 `arrayMove` 규칙을 공유해서, 드래그 중 미리보기와 저장 결과가 어긋나지 않습니다.

```
① 드롭   : over.id는 칩 이름 또는 카테고리 컨테이너(zone-N)
② 번역   : zone-N에 놓으면 "그 카테고리 맨 뒤로 이동"으로 해석
③ 반영   : 저장(moveChipState)과 화면(computeSnapshotMove)이 같은 규칙으로 갱신
```

개발 중 자주 보였던 "앞으로 못 옮김", "놓은 자리에 갔다가 되돌아감", "새로고침하면 옛 순서로 복귀" 증상을 원인별로 해결했고, 각 수정마다 검증 케이스를 추가해 재발을 막았습니다.

### 모바일 터치
롱프레스(600ms), 이동 허용 범위(10px), 세로 스크롤이 충돌하지 않도록 `touch-action`을 상태에 따라 전환합니다. 평소에는 `pan-y`로 스크롤을 살리고, 드래그 중에만 `none`으로 바꿉니다.

### 저장과 마이그레이션
`fridge-chips:v4` 키 하나만 저장 소스로 씁니다. 저장된 값을 전수 검증하고, 하나라도 어긋나면 부분 복구 대신 기본값으로 초기화합니다. 구버전 데이터가 있으면 안내와 백업 복사를 제공합니다.

## 실행, 검증, 배포

```bash
cd app
npm install
npm run dev       # 개발 서버
npm run build     # dist/ 생성
npm run preview   # 빌드 결과 확인
```

```bash
node app/verify/v16-logic-test.mjs    # 드래그·저장·스크롤 59케이스
node app/verify/v162-logic-test.mjs   # 프롬프트 생성 27케이스
node app/verify/v163-logic-test.mjs   # 착지 번역·화면/저장 일치 38케이스
node app/verify/var-scan.mjs          # var, window. 사용 여부 스캔
node app/verify/_kor-scan.mjs         # 소스 파일 인코딩 파손 스캔
```

5종 합계 124케이스 통과를 공식 검증 기준으로 삼았습니다. main에 푸시하면 GitHub Actions가 Node 20에서 빌드해 Pages로 배포합니다.
verify-legacy/의 스크립트는 v1.2~v1.4 스펙 기준이라 현행 코드에서 FAIL이 나옵니다 (정상, 게이트 아님).

## 이 프로젝트에서 보여주는 역량

1. React 구조 설계: 컴포넌트 5개, 커스텀 훅 2개, 순수 로직 모듈로 계층을 분리했고, `useRef` 스냅샷으로 렌더 중 부수 효과 없이 dnd-kit과 상태를 맞췄습니다.
2. 드래그앤드롭 심화: 입력 장치별 센서를 분리하고, 미리보기와 저장 규칙을 하나로 통일했습니다.
3. 모바일 UX: 롱프레스, 이동 허용 범위, 세로 스크롤 사이의 충돌을 해결했습니다.
4. 영속성 설계: 버전 키, 전수 검증, 결정적 초기화, 마이그레이션 안내를 갖췄습니다.
5. 테스트 설계: UI 로직을 순수 함수로 분리해 별도 테스트 러너 없이 124케이스로 회귀를 막았습니다.
6. CI/CD: GitHub Actions 자동 배포와 하위 경로 대응, 배포 후 라이브 자산 검사까지 구성했습니다.
7. 리팩토링: 5단계 커밋마다 검증 게이트를 통과시키며 기능 변화 없이 src를 약 25%, CSS를 약 27% 줄였습니다.
